# retail_mini

One year (16 Mar 2014 – 15 Mar 2015) of receipts from a generated German supermarket chain – a small star schema
for SQL practice. The Exacademy course *The Exasol flavour of SQL* loads it into the schema `RETAIL` in its first
lesson, and uses it from there on.

| File | Rows | One row per |
|---|---|---|
| `SALES.csv` | 100,001 | receipt |
| `SALES_POSITIONS.csv` | 1,047,037 | line on a receipt (31,464 cancelled) |
| `ARTICLE.csv` | 5,476 | product (German names, English product groups) |
| `MARKETS.csv` | 100 | store, with longitude/latitude |
| `CITIES.csv` | 93 | city, with latitude/longitude |
| `DIM_DATE.csv` | 356 | day with sales |

**Load it into Exasol Personal** (starter kit): create the tables with their exact types first, then load the
whole folder – at the second question, type `RETAIL` as the target schema.

```bash
exapump sql -p starter-kit < ~/retail_mini/retail_mini.sql
exakit data-load ~/retail_mini
```

The files have a header row and are comma-separated, UTF-8, with LF line endings. `MARKETS.POSTAL_CODE` lost its
leading zeros in the source data (`4317` for Leipzig); `CITIES.ZIP_CODE` has them (`04317`).

**Origin and license:** generated by Exasol for training (the old Exacademy `retail_mini`, reworked 2026-11-18:
header rows added, line endings normalized, the always-empty columns LOYALTY_ID, VOUCHER_ID and TMP_OLD_NR
dropped). Free to use for Exasol training.
